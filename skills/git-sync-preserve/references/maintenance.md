# 维护检查与沙箱场景

最后更新：2026-10-25

维护技能时检查以下内容；本文件是验收清单，**不是这些场景已经通过的声明**。

## 结构

- `SKILL.md` 的 frontmatter 仅需 `name: git-sync-preserve` 和含三类触发分支的中文 `description`；目录名与 name 一致。
- 所有文档 UTF-8、LF，相对链接在复制整个技能目录后仍存在；无运行时本机路径或特定产品工具依赖。
- 索引名称／链接／日期一致；技能目录只有入口、实际引用资料和必要维护测试。备份、报告、日志与沙箱留在仓库外。
- 静态审阅确认每个修改入口都有授权门、检查点、冲突停机、恢复和验证出口；用户显式暂停优先于默认自动执行。

## 行为

在环境提供的临时目录（可用时优先 `/tmp/opencode/`）创建私有唯一沙箱；独立 bare 远端和至少两个本地 clone。
仅在沙箱设置虚构提交身份、禁用交互提示，不修改全局配置；所有写入／push 都只指向沙箱。
使用普通文本、二进制、点文件、链接和删除样例；记录命令退出码、树 OID、哈希和索引映射。按场景实际执行技能步骤或由测试代理执行，报告区分 Git 原语测试与完整代理行为测试。

| 场景 | 明确预期 |
| --- | --- |
| 干净 main 落后／领先／相等 | 分别快进／保留本地 tip／不变；双方备份读回正确且为结果祖先 |
| 两端分叉、改动不同文件 | merge commit 包含双方 tip，普通显式 push 成功，无重写 |
| 用户要求“先等确认” | 只 fetch、诊断和展示独有提交；本地分支／index／文件／stash 不变，未 push |
| 原有 staged＋同文件 unstaged、二进制、删除、点文件／链接和已有 stash | 清理前备份读回正确；恢复后两个层次内容／mode／类型一致；旧 stash 保留，新 stash 以完整 OID 引用 |
| 本地脏文件与新上游完全一致 | 允许变干净；原版本保留，不为了凑脏文件数反向修改上游 |
| stash 恢复与上游同路径冲突 | 临时副本先发现，live 字节和索引未变，等待人；无自动选边 |
| 原索引无 staged 差异，人工批准恢复冲突 | 仅指定路径取消冲突处理引入的暂存，文件保留批准结果，索引恢复无 staged 意图 |
| 上游占用未跟踪／ignored 同名路径 | 内容不同或未保护即停；ignored 原件不被覆盖，未跟踪双方版本均保留 |
| dirty 子模块／嵌套仓库、稀疏检出、特殊 index 标志或不可重现过滤器 | 能力不足时清理前停止，不声称完整快照 |
| 编辑器仍写入、快照读回失败、配额不足 | 清理前停止；不删除其他任务／备份来腾空间 |
| 推送前远端新增一次提交 | 再建检查点，merge 后重验，再普通 push；原全部 tip 为祖先 |
| 远端持续变化／push 间竞态 | 最多两次额外同步尝试，之后明确阻塞；无无限循环或强推 |
| 分支保护拒绝／项目测试失败 | 保留本地候选与原工作，报告阻塞，不绕过保护或推送失败验证的版本 |

## 证据边界

每次交付列出实际执行的场景、命令／脚本位置、结果与跳过项。
Git 原语在沙箱通过不等于代理完整遵守流程，也不证明目标项目可运行；项目验证与真实并发写入协调仍由实际同步任务负责。
