# 关键词与市场调研

以**零新增支出**为默认预算，用免费资源和已有会员权益取得证据。候选词、搜索热度、搜索量、竞品流量和付费需求分别验证；一个信号不能替代其他信号。本技能替代对 Web.Cafe 付费 API 的依赖。

## 1. 定义决策

明确本次要决定什么：选内容词、寻找竞品、验证工具需求，还是筛选一个细分市场。记录产品/用途、目标客户、国家、语言、时间窗、种子词或域名，以及已有账号和预算。

- 已给出的范围直接采用；缺失信息会改变结论时，只追问关键项。探索请求可先按带标签的假设启动。
- 国家、语言未知时，保留未知或说明临时假设；中文沟通不等于中文市场。
- 默认不新增订阅、购买 API、开广告或更改监控。零新增支出允许使用已有订阅内权益与预付额度，不等于只用免费账号。订阅内只读功能优先；会扣 credits/计次额度的调用先核实成本和余额，并确定本轮上限。

**完成条件：** 决策问题、市场范围、假设和资源上限均可复述；没有把缺失输入补成事实。

## 2. 选择可用渠道

按任务挑选最短取证路径，不要求每个渠道都跑一遍：

| 证据需要 | 首选路径 | 按需读取 |
| --- | --- | --- |
| 新方向、长尾词、季节性和搜索意图 | 搜索结果、下拉建议、Google Trends；有现成权限再用 Keyword Planner、Bing 或 Ahrefs 免费工具 | [免费资源](references/free-resources.md) |
| 竞品关键词、流量、广告或市场榜单 | SiteData 关键词/流量界面、AITDK 流量与页面分析；已有授权且费用明确时再用官方 MCP/CLI | [会员工具](references/member-tools.md) |
| 自有站真实曝光、点击和查询 | 已授权的 Search Console 或 Bing Webmaster Tools | [免费资源](references/free-resources.md)的自有站分支 |
| 痛点、替代方案、付费意愿 | 实际产品与定价页，以及相关讨论、评论、客户证据 | [免费资源](references/free-resources.md)的市场分支 |

发现当前会话的浏览器、网页读取、MCP 和 CLI 能力；有 `agent-reach` 时按其路由读取公开内容。运行时以工具 schema、官方 Catalog 和当前页面为契约。

为选中的渠道记录：访问是否成功、权限/额度是否核实、能提供什么指标、适用地域/时间、阻塞原因。已知 SiteData 套餐和选路规则见[会员工具](references/member-tools.md)；采用用户已说明的套餐，不重复追问。扩展已安装不等于已登录，订阅时长不证明余额或到期日。

### 执行契约与回退

先把本文件所在目录解析为 `skill_root`；脚本、测试和本地参考资料都从 `skill_root` 定位，不假设当前工作目录就是技能目录。事实来源按以下顺序处理：当前账号状态、运行时 schema/Catalog 和当前页面 > 用户在本轮提供的约束与证据 > 本技能 references 中的静态资料。静态资料只能说明默认能力，不能覆盖当前权限、价格或余额。

每个渠道开始前记录 `not_attempted`；完成后只使用以下状态：`succeeded`、`partial`、`blocked` 或 `failed`。出现空响应、部分响应、非法格式、超时、401/403、429、用户取消或超出预算时，保留已取得的原始证据，标记原因，停止当前渠道并切换到下一条可用路径；没有下一条路径时交付受限结果，不把失败改写成零需求。

| 触发情况 | 立即动作 | 仍失败时的兜底 |
| --- | --- | --- |
| 浏览器、桥或侧边栏不可读 | 记录 `blocked`，改读公开网页或官方导出 | 交付已读证据与缺项采集计划 |
| MCP/CLI 未连接、状态异常或 Catalog 为空 | 不猜工具名；保留状态输出，改走免费渠道 | 标记会员数据未完成 |
| 权限、费用、余额或副作用未知 | `🛑 STOP` 当前调用，不安装、不扣 credits、不启用监控 | 只用已确认免费或已授权的只读渠道 |
| 返回 401/403、429、签名错误或超预算 | 停止当前来源，不重试碰运气、不换身份绕过 | 使用其他来源并降低结论置信度 |
| 证据不足以支持推荐 | 不排序或下强结论 | 交付未知项、反证和最小验证动作 |

### 🔴 CHECKPOINT：安装、授权与付费调用

在安装包、修改持久 `PATH`/全局配置、启动 OAuth/MCP、扣 credits、导出账户数据或启用持续监控前，先停止并列出：目标动作、所需权限、预期副作用、单次成本、总上限和回退方案。仅为本次命令定位用户已安装运行时而临时补充进程级 `PATH` 不属于持久修改，但不得写入 shell 配置或系统环境。费用、权限或副作用任一项未知，或用户未在本轮明确授权时，保持 `STOP`，改走已确认的公开/免费路径。浏览器授权必须由用户亲自完成；不索取或搬运授权码、回调 URL、令牌、Cookie 或扩展存储。

### SiteData CLI 安装与授权

- 选用 CLI 时先检查 `node --version`、`npm --version` 与 `sitedata --version`，不能只凭 `command -v sitedata` 判断可用。出现 `env: node: No such file or directory` 时，先定位当前用户已安装的 Node.js，在本次命令的 `PATH` 中补入其可执行目录后重试；不因此重装 CLI、更换运行环境或读取凭据。确实缺少运行时且无安装授权时，说明阻塞并使用其他可用渠道。
- 选定 SiteData CLI 且检测不到 `sitedata` 时，若用户已在本轮明确要求安装或授权安装，先读取官方安装指南，检查 Node.js 20+ 与 npm，然后自动运行 `npm install --global @sitedata-dev/cli` 和 `sitedata --version`；没有明确授权时不改全局环境，先说明阻塞。
- 安装不等于登录。先运行 `sitedata auth status`；仅当结果表明未授权且用户已明确允许本轮授权时，才运行 `sitedata login`，把浏览器授权交给用户。用户完成后再次运行 `sitedata auth status`，再运行 `sitedata list --output json`，确认授权有效且在线 Catalog 非空，再调用具体 API。
- 具体 API 以本次 `sitedata list --output json` 返回的 Catalog 为准；先用 `sitedata describe <command> --output json` 核对参数。若用户指定的只读命令不在 Catalog 中，先报告“当前 CLI 不支持/不可用”，不得改名、猜别名或静默替换；用户明确要求诊断该命令时，最多原样执行一次并记录 stdout、stderr 和退出码，仍不得把结果当作受支持能力。非只读命令直接停止。
- CLI 的安装、登录命令与后续自动化必须使用同一操作系统用户与运行环境；浏览器仅用于用户完成 OAuth 授权，不要求与 CLI 处于同一沙箱。不要搬运浏览器 Cookie、扩展存储或系统凭据。
- 绝不读取、打印、复制或写入已保存的 OAuth Token、API Key、授权码、回调 URL 或其他秘密。安装、登录和 Catalog 验收通过后仍须按当前命令说明核对权限与扣费，不把 CLI 存在当作数据已取回。

**完成条件：** 至少一条相关渠道返回非空原始证据，或明确记录不可用并进入受限交付；不以“工具存在”代替取数验收。

## 3. 发现候选

从少量种子词或直接竞品开始，按用途、受众、修饰词、替代方案和购买意图扩展。保留原始语言，按意图聚类，区分品牌、导航、信息和交易查询。根据决策需要决定扩展规模。

需要无密钥的下拉建议时，从已解析的 `skill_root` 运行：

```sh
python3 "$skill_root/scripts/fetch_suggestions.py" --query "invoice generator" --language en --country us
```

脚本只读取 Google 的非正式公开建议端点，输出 JSON 到标准输出；最多十个显式查询，有限流保护。语言和国家参数只是请求提示，不证明实际用户所在地，也不提供月搜索量、CPC 或难度。被拦截时改用可见网页，不把它视为有服务保证的免费 API。

收集竞品时优先匹配用户任务和商业模式，分开直接竞品、替代方案、内容站与聚合站。热门榜单只是发现入口，不能直接证明细分市场值得进入。

**完成条件：** 每个候选能回溯到种子与真实来源；品牌词和同意图近似词已归组，没有把建议排名写成搜索量。

## 4. 验证需求与进入难度

对最有可能改变决策的候选补证据：

- **需求：** 对齐市场和时间窗后核对 Trends、可获得的关键词量、自有站查询或相关讨论。只有下拉建议时，结论停在“发现候选”；只有趋势时，停在“相对热度变化”。
- **搜索入口：** 读取当前搜索结果，记录查询、可确认的地域/语言、日期、结果类型、广告和主要竞争页面。无法确认定位时标注限制，不宣称取得某国精确排名。
- **竞品：** 读取实际产品、定价与目标页面，辅以 SiteData/AITDK 估算；区分全站流量与该词/该落地页流量、有机与付费、品牌与非品牌。
- **市场：** 结合痛点、替代方案、价格、评价和广告观察判断需求。广告存在只支持“有人投放”，不能推出预算、利润或留存；搜索量不是市场规模。

标注来源是否独立。两款插件可能共享底层数据；不知道供应商关系时，写“独立性未知”，不算两份独立验证。估算冲突先检查地域、日期、覆盖范围和口径；仍冲突则并列展示，不能任意平均。

难度可作有依据的定性判断，如品牌垄断、意图错配、强内容或新进入者。只有工具确实返回 KD 时才引用其数值，附供应商；不从 CPC、广告或插件的 DR 推导数值 KD。

**完成条件：** 推荐候选拥有与结论相称的证据；关键缺项、相互矛盾与不利证据均保留，未核实的数字不参与排序。

## 5. 交付可验证结论

根据任务裁剪交付：

1. **范围与渠道：** 市场、时间窗、假设、实际成功/失败的渠道、使用的权益和额度。
2. **关键词表：** 词/意图簇、客户用途、需求信号、量或区间、竞争证据、建议动作、置信程度与来源。
3. **市场判断：** 优先机会、反证、竞品与替代方案、尚缺的付费需求证据；说明哪些观察会推翻推荐。
4. **下一步：** 最小验证动作、指标、期限和停止条件；新增花费或账号写操作另行确认。

每项关键证据至少包含 `source`、`source_url` 或可定位的界面证据、`observed_at`、`scope`、`metric_kind`、原始值及单位/范围。标记为用户证据、直接观测、平台实测、供应商估算或推断；搜索建议和 Trends 属于直接观测的信号，不是搜索量实测。

缺失值用 `null`/“未知”，与真实 `0` 分开。Keyword Planner 的区间保留区间；不取中点制造精确值。估算保留供应商精度，不叠加近似词或跨平台流量制造 TAM。

单次响应、导出、截图和报告放系统临时目录的独立任务子目录；用户要求持久保存时使用其指定位置。账号秘密不进入证据。最终明确本次实际调用、验证通过项、未运行项和仍需用户完成的登录/授权。

建议每条关键证据按以下结构记录，缺失字段使用 `null`，不要用空字符串或 `0` 代替未知：

```yaml
source: "供应商、页面或用户提供"
source_url: "可定位 URL；无则 null"
observed_at: "YYYY-MM-DDThh:mm:ss+TZ"
scope: "国家、语言、设备、时间窗、域名或页面"
metric_kind: "autocomplete_suggestion | trend_index | search_result | provider_estimate | first_party_search_analytics | other"
raw_value: null
unit: "次/月、区间、指数、排名或 null"
evidence_type: "user_evidence | direct_observation | platform_measurement | provider_estimate | inference"
limitations: "口径、覆盖、定位和独立性限制"
```

**完成条件：** 关键判断能追溯到本次读取的证据；来源不可用时交付带缺项的假设和采集计划，不冒充已完成数据调研。

## 不要做什么

- 不把下拉建议、Trends 指数、广告竞争、CPC、DR、访问量或榜单排名改写成月搜索量、SEO 难度、收入、留存或 TAM。
- 不把安装成功、订阅期限、连接免费或公开套餐额度改写成当前登录有效、余额充足或本次调用免费。
- 不把两款可能共享底层数据的插件当作两份独立验证，不把冲突估算取平均，不用中点制造精确值。
- 不读取或转移 Cookie、扩展存储、OAuth Token、API Key、授权码和回调 URL；不绕过验证码、权限、签名接口、429 或额度限制。
- 不把自有站 Search Console 数据用于证明竞品曝光或市场总量；不把竞品供应商估算冒充第一方实测。
- 不在缺少关键范围、原始证据或相反信号时给出确定性推荐；只能交付受限结论和下一步验证。
