# 给 p3l.me 添加条目

交付是一条 `src/content/sites.json` 对象、对应本地素材和持久证据，生成 `/sites/{slug}/` 与 `/zh-cn/sites/{slug}/`。所有路径相对 p3l.me 仓库根目录；按适用的 `AGENTS.md` 和实际检出位置定位仓库（Debian 服务器为 `/srv/workspaces/p3l.me`，Fedora 为 `~/workspaces/p3l.me`）。

## 1. 锁定范围

先读适用的 `AGENTS.md`、`MEMORY.md`、`PRODUCT.md`、`LESSONS.md`、`APP_FLOW.md`，检查工作区已有改动。字段以当前 `src/content.config.ts` 为准，校验以 `scripts/check-content.cjs` 为准；同分类邻近条目只提供写法和键顺序，不是字段清单。

改文件前明确公开名称、官网 URL、展示域名、`slug` 与分类。`id` 等于小写短横线的 `slug`；检查 id、slug 和官网域名是否已有条目。

- 用户指定且存在的分类直接用；没有指定时，选描述产品大类的现有分类。具体能力放标签。
- 没有准确的大类时，先在临时草稿拟定双语分类，沿用现有对象结构，`id` 等于 `slug`，`sortOrder` 为当前最大值加 1；通过步骤 4 的落盘门槛后，与条目一起追加到 `src/content/categories.json`。分类存数据文件，不改 `src/data/navigation.ts`。
- **STOP：** 用户指定的分类不存在或与官方产品定位冲突时，说明差异并询问一次；未确认前不另选分类、不发布条目。MoR 结账通常属于 `payment-gateway`，`merchant-of-record` 是能力标签，但不能据此覆盖用户的指定分类。
- **STOP：** 已有同站点条目且不属于本次收录时，报告匹配对象，不重复添加，也不擅自改成更新任务；用户确认更新后按更新范围处理。

本次新增对象进入验收后，用户指出的截图、文案或证据问题属于收录纠错。只修受影响的字段、素材和证据，复用仍有效的依据；不重复追加对象，不顺手修改其他站点。

## 2. 核对事实和 DR

读官网及本次要引用的定价、功能、平台、许可证页面。按 `agent-reach` 技能选择可用读取方式；证据必须来自本次实际读取的官方内容。抓取失败时换官方文档或可用浏览器；仍无法核实时，报告缺项，不靠搜索摘要或旧条目填事实。

DR 遵循当前项目规则，优先请求官方端点：

```text
https://api.ahrefs.com/v3/public/domain-rating-free?target={域名}&output=json
```

检查 HTTP 状态和 DR 字段，保存响应依据；值必须为 0–100 整数，记录的 `target` 与请求域名一致，响应若带目标域名也要核对。用户提供的 DR 整数只是待核对线索，不能代替 API 响应或证明来源。已有安全凭据时按官方要求认证，凭据不写进仓库、命令回显或证据文件。

`domainRating` 写 `value`、`target`、`sourceName: "Ahrefs"`、真实请求的 `sourceUrl`、`licenseUrl: "https://ahrefs.com/legal/domain-rating-license"` 和实际读取日的 `checkedAt`。把域名、日期、整数、请求地址及结果补进 `curation/domain-rating-evidence.md`；响应原件、摘录和临时截图放系统临时目录的独立任务子目录。

**STOP：** 403、需要但缺少 API key、非成功响应、目标不符或整数无效时，不新增公开对象。报告错误和需要的外部条件。当前项目要求 API 来源，Authority Checker 的整数不能自动替代，也不能把 Checker 数据标成 API 响应；历史 Checker 记录不构成本次授权。用户明确授权例外后，先协调项目来源规则、校验和证据格式，不能仅换一个 `sourceUrl` 蒙混通过。

## 3. 准备本地素材

先在临时目录准备并检查，全部合格后才放入公开目录。

- 图标：`public/logos/sites/{slug}.png`；官方仅提供 SVG 时使用同名 `.svg`。优先官方方形 favicon、apple-touch-icon 或独立 icon SVG。横版字标只有在图形可分离时才裁出标志并调整 viewBox；保留图形需要的 defs、遮罩等结构。检查宽高比 0.8–1.25，栅格化后没有产品名、标语或一行字。透明标志在奶油色底上不可辨认时，铺不透明底色再检查。
- 截图：公开官网首页，1440×900 CSS 视口、设备像素比 1、非整页截图，输出原始 1440×900 PNG，保存为 `public/snapshots/sites/{slug}.png`。完整显示指首屏内容加载完整，不是截取整页长图。

### 首页截图验真

- **真实页面：** 先读当前捕获脚本和浏览器能力；优先使用可用的真实 Chrome 会话，确认最终 URL 是公开访客首页，并回到顶部。脚本绑定不存在的 Chrome 路径时，换本机已有浏览器，不安装浏览器或修改全局配置。
- **渲染完整：** 等主内容、字体及首屏关键图片或视频封面加载稳定后截图，再目视核对导航、主标题、布局和媒体。HTTP 200、network idle 或尺寸合格不能证明完成；空白占位、骨架屏或缺少主视觉仍不合格。需要触发懒加载时正常滚动后回到顶部；遮挡通过页面正常控件处理，不改 DOM、隐藏业务内容、拼贴或拉伸来伪造首页。
- **参考对照：** 用户提供真实浏览器截图或指出不一致时，核对 URL、视口、登录、Cookie、语言及页面版本，再与真实会话对照并重新捕获。可核实的地区或 A/B 差异说明依据；不能把自动化浏览器结果默认当成正确版本。关键内容仍不同且无法解释时，报告截图验收未完成。

**STOP：** 图标仍是字标，截图缺失、尺寸不符、首屏加载不完整，或截图是登录、验证码、错误页时，不新增公开对象。需要人工登录或验证码时交回用户完成，不绕过验证；恢复后重新捕获官网。本次收录纠错未通过上述检查时，也不能宣称截图已修复。

## 4. 写条目和证据

使用当前 schema 的字段，沿用邻近条目的键顺序。`sortOrder` 为当前最大值加 1，只表示展示顺序。`createdAt`、`lastCheckedAt`、`lastReviewedAt` 按本次实际操作日期填写，不能从邻居复制。双语文本包含非空的 `en` 与 `zh-cn`；`pro`、`con` 可以是空数组，两种语言的条数必须一致。

### 字段和标签

- **定位锚点：** 用核实的官网事实确定产品类型，并保持 `oneLine`、`editorialSummary`、`scenarios`、`notFor`、分类、标签与 `useCases` 相互兼容。编辑摘要扩写功能和边界，不另换产品定位；例如短描述定为“创作者主页”时，摘要也沿用“创作者主页”，而非改叫“变现平台”。中英文字段逐项核对类型、功能和限制；若证据要求纠正定位，联动修正本条目受影响的双语字段，分类调整仍受步骤 1 的授权约束。
- **不带回旧字段：** `coreValue` 已删除，用 `pro` 承担有证据的长板；不写 `curationStatus`、`alternatives`、`monthlyVisits`。旧模板先按当前 schema 清理，而不是复制整套键。
- 分类用步骤 1 锁定的值。标签只写本次确认的直接能力，优先复用 `src/content/tags.json` 中准确的 id；无准确标签且用户未禁止新增时，沿用现有结构追加并让新条目引用。id 小写短横线，label 使用规范英文 Title Case，`aliases.en`、`aliases.zh-cn` 为数组；中文别名只用于搜索，显示名称保持英文。
- **STOP：** 用户禁止新增标签，而旧标签会把产品描述成另一类东西时，说明冲突并确认，不悄悄新增或误挂。例如官方 Skill 接入不等于 `agent-skills` 能力；这种接入方式不作为标签或 `useCases`。
- `useCases` 写直接用途并复用已有短横线用语。许可证状态放 `softwareLicense`，不是标签或长板；确认闭源才写 `Proprietary` / `闭源`，官方仓库明确开源时写核实的许可证，未核实则写 `License unverified` / `许可证待复核`。
- `notFor` 写官网证据支持、对本品用户有判断作用的产品边界，不拿“要找别的分类的人”充数。该字段当前必填；没有能核实的边界时，先补证据，仍缺失则条目未完成，不填空字符串、不改 schema。

### 优缺点

每条只写本品已核实、对选择有影响的长短板，不点名竞争对手、不复述适用场景或许可证。短句应呈现实际差异，如收费条件、到账机制、获客方式或责任边界，而非“功能丰富”“操作简单”等泛泛评价。中文每条不超过 25 字，英文不超过 8 个词；没有证据就留空数组，不为对称凑条数。

写非空 `pro` 或 `con` 前，选至少一个同一细分赛道、面向相同用户的典型对手，直接读取双方官方页面。每条候选都对照相同能力，记录本品事实、对手事实及各自适用条件；正向长板也需差异证据，不只核对否定句。费用对照区分平台费与支付处理费，并写明计划、用户条件及生效日期。“没有 / 不是 / 不支持”需确认对手有、本品没有；差异不必是本品独有，但必须真实且对选择有影响。未核实、赛道共有、不重要、只来自本品对比页的对手数字及跨赛道比较不保留。MoR 结账对照其他 MoR，不用 Stripe 这类非 MoR 支付服务替代。

按 `curation/pro-con-evidence.md` 最近一节的表格补读取日期、双方实际读到的 URL、差异对用户的影响、保留或删去的依据及对应双语短句；对手名字和完整对照只放证据表，不放公开句子。没有对手原文时写明缺证据、不保留，不虚构双方出处。校验拒绝场景腔（如“用于”）或其他措辞时，修正或删掉该条；不放宽校验脚本。

### 落盘门槛

只有官网事实、分类、标签、DR、必填双语字段、合格图标和截图均齐备后，才把素材和对象加入公开目录。阻塞时保留临时草稿、列出缺项，不新增悬空分类或标签，也不改成 `unverified` 发布残缺条目。已有用户改动不属于清理范围。

## 5. 同步和验证

更新 `docs/P3L.ME_项目看板.md` 的实际公开数量，并记录本次日期、站点与分类。`MEMORY.md` 有被本次复核推翻的旧结论时，用实际日期补充说明；不因单条收录重写整份文档。

运行 `npm run content:check`，再运行 `npm run build`，并检查 `git diff --check`。`node` 或 `npm` 不在 PATH 时找本机已有的同一套工具链，仅为当前命令补 PATH，不安装运行时或修改全局配置。依赖确实缺失时先读包管理器和锁文件，按项目方式安装；安装前保存锁文件副本到临时目录，逐项核对安装差异，保留用户已有修改，不能用整文件还原抹掉它们。

验收分开检查，技术校验通过不能代替内容与素材验收：

- 命令成功；构建存在 `dist/sites/{slug}/index.html` 和 `dist/zh-cn/sites/{slug}/index.html`，两页无 Core value 节。
- 核对构建页面的短描述、编辑摘要、场景和优缺点，确认同一产品定位、中英事实与限制对应；非空优缺点逐条能追溯到双方差异证据。
- 查看实际引用的本地图标与截图，按步骤 3 验真并核对像素尺寸；看板数量等于实际条目数。

失败时修本次引入的问题，不修无关问题；既有检查失败要标明范围，分别报告已通过和未通过的验收项，不能笼统宣称全部完成。

## 6. 交付和后续授权

交付 `slug`、分类、DR 整数及实际来源、改动文件、两条校验结果、未完成事项。未提交时明确改动仍在工作区；没有要求提交就不提交、不推送。

用户要看页面时，用已构建的预览确认本机地址返回 200，再打开中英文首页和详情页。验收指定分类、双语文字、图标、截图、DR；请用户用真实移动端 390px 视口检查无横向滚动、文字可读、触控目标和筛选交互，同时检查受影响的桌面视图。

分支、rebase、提交与推送流程遵循适用的全局及项目 `AGENTS.md`，本技能不提供豁免。用户要求提交时，先展示双语 Conventional Commits 信息和本次文件清单，等用户确认措辞后只提交本次改动；未要求提交或推送时不自行执行。Git 操作仅限项目仓库，不提交其他工作区改动，不做会丢弃用户改动的整文件还原。

## 维护测试

`test-prompts.json` 是复用的行为回归用例。用隔离目录和离线证据夹具测试字段、来源、授权与失败分支；测试中的 `.test` / `.example` 域名不是真实待发布站点。单次评估日志、报告、截图和备份留在系统临时目录，不同步进技能目录。区分文件结构校验、实际执行的行为回归与真实线上验收；JSON 可解析不等于行为用例已通过，干跑不能替代真实官网读取、截图或构建。
